# University Course Allocation — Spring Boot API

A minimal Spring Boot REST wrapper around the original University Course
Allocation algorithm (ported earlier from C++ → Java). The algorithm itself
is untouched; only the way input goes in and output comes out has changed,
from files (`input.txt` / `output.txt`) to an HTTP JSON API.

## What's Spring Boot here (and nothing else)
- **Spring Web** — `@RestController`, `@PostMapping`, JSON request/response binding
- **Spring Validation** — `@Valid` + `@NotBlank` on the request DTO
- **Spring exception handling** — `@RestControllerAdvice` turns bad input into a clean `400` JSON error instead of a stack trace
- **Spring Boot Test** — `@SpringBootTest` + `MockMvc` test hitting the real endpoint with the project's own sample data

No database, no security, no extra layers — just enough Spring Boot to have
a real, working, testable REST API.

## Run it
```bash
mvn spring-boot:run
```
Requires internet access on your machine the first time, so Maven can
download the Spring Boot dependencies from Maven Central.

## Try it — two ways

### Option A: upload input.txt directly (easiest)
No JSON escaping needed — point curl (or Postman) straight at your existing `input.txt` file:
```bash
curl -X POST http://localhost:8080/api/allocate/file \
  -F "file=@input.txt"
```
This prints the output directly in your terminal, formatted exactly like the
original `output.txt`. To save it to a file instead:
```bash
curl -X POST http://localhost:8080/api/allocate/file \
  -F "file=@input.txt" \
  -o output.txt
```

**In Postman:** new request → POST → `http://localhost:8080/api/allocate/file`
→ Body tab → `form-data` → key `file`, type `File` → choose your `input.txt`
→ Send.

### Option B: send input as a JSON string
```bash
curl -X POST http://localhost:8080/api/allocate \
  -H "Content-Type: application/json" \
  -d '{"inputText": "7\npC,0.5,0,0,1,fde1,0\npD,1,0,0,1,fde1,1,hde1\npB,1,0,1,hdc1,1,fde1,0\npE,0.5,1,fdc1,1,hdc1,0,0\npA,1,2,fdc1,fdc2,0,0,0\npF,1,1,fdc1,0,0,0\npG,1,1,fdc1,0,0,0\n"}'
```
Response:
```json
{
  "result": "Courses:     Professors in order of priority:\nfdc1           pE pA pF pG \n..."
}
```
Useful if the input is generated by code rather than read from a file.

## Project structure
```
src/main/java/com/university/allocation/
  AllocationApplication.java        - Spring Boot entry point
  controller/AllocationController.java  - POST /api/allocate and /api/allocate/file
  service/CourseAllocationService.java  - the original algorithm (instance-scoped now, not static)
  dto/AllocationRequest.java         - request body + validation
  dto/AllocationResponse.java        - response body
  exception/AllocationException.java     - custom error for bad input
  exception/GlobalExceptionHandler.java  - converts exceptions to JSON errors
src/test/java/com/university/allocation/
  AllocationControllerTest.java      - end-to-end test using the sample input.txt data
```

## What changed vs. the plain Java version
| Original (`CourseAllocation.java`) | This version |
|---|---|
| `static` fields, shared across the whole program | instance fields on `CourseAllocationService`, reset every call — safe for concurrent requests |
| Reads `input.txt` from disk | Reads `inputText` from the JSON request body |
| Writes `output.txt` to disk | Returns `result` in the JSON response |
| `main()` runs once per process execution | `/api/allocate` can be called repeatedly, from a browser, curl, Postman, etc. |
| No input validation | `@NotBlank` rejects empty input with a `400` before the algorithm even runs |
| Errors would throw raw Java exceptions | Malformed input returns a clean `{"error": "..."}` JSON response |

The `assign()` recursion and the course-id renumbering logic are line-for-line
identical to the original.
